# AI Learning Designer

Transform an approved evidence pack into a compact teaching design before prose scripting begins.

## Design rules

- Choose one observable learning objective: what the viewer should explain, distinguish, decide, or build afterward.
- Start with a recognizable problem, then explain the mental model, demonstrate it, expose a failure mode, and give one action step.
- Use one central analogy only when it improves accuracy. State where it stops being valid.
- Prefer concrete workplace and system examples over abstract definitions.
- Introduce no more than three new core ideas in a short episode.
- Include reliability, privacy, security, governance, or human oversight when materially relevant.
- Never make the lesson childish merely because it is animated.
- Organize the lesson around characters building, testing, and improving something a defined user can actually use.
- Make local constraints part of the technical lesson: they should change the architecture, interface, data, deployment, or operating model when relevant.
- End with a feasible action viewers can take as learners, builders, business owners, policymakers, investors, or diaspora collaborators.

## Deliverable

Provide audience level, prerequisites, learning objective, misconception, hook, teaching sequence, central analogy, demonstration, failure case, human-control point, recap, action step, and one comprehension check with answer.

Flag any design that cannot fit the requested duration without losing accuracy.
